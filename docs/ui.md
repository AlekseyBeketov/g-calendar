# UI specification — Google Calendar / Tasks for macOS

## Направление

Нативное macOS-приложение на SwiftUI/AppKit: утверждённая система Pixel Paper с белыми поверхностями, синим акцентом и компактными строками задач с метаданными Color Atlas. Полный контракт — design/DESIGN.md; источник значений — Sources/GCalendar/ThemePalette.swift, нативный rendering adapter — Sources/GCalendar/AppTheme.swift. Сохранить привычную macOS-навигацию, toolbar, sidebar, меню и поведение окон; это визуальное направление, а не копирование чужих экранов или ресурсов. Основной рабочий режим — неделя календаря с одновременной видимостью событий и задач; список задач — равноценное, быстро доступное представление.

## Структура и навигация

- **Основное окно:** стандартный `NavigationSplitView`: sidebar слева, рабочая область справа; native toolbar сверху. Sidebar ориентировочно 220–260 pt, с системным изменением ширины и сворачиванием.
- **Sidebar:** переключение «Календарь» / «Задачи»; далее календари в календарном разделе, task lists в разделе задач. Одна группа фильтров находится в header рабочей области задач. Селекторы показывают цвет/имя и выбранное состояние; видимость календаря переключается независимо от выбора. Не смешивать селектор task list с фильтром календаря.
- **Toolbar рабочей области:** календарные назад/вперёд и «Сегодня» доступны только в календарном разделе; поиск относится к текущему разделу. Заголовок периода/списка и создание находятся в адаптивном header рабочей области. Меню выбора вида и фильтров — нативные; не превращать toolbar в ряд мелких кнопок.
- **Week-first calendar:** неделя — вид по умолчанию, с явным диапазоном дат и удобным переходом между неделями. События и задачи различимы одновременно: события отображаются блоками по времени, задачи со сроком — отдельными компактными date-only элементами с чекбоксом, а задачи без срока — один раз в компактной сворачиваемой зоне «Без срока» вне дней, без искусственного назначения даты и дублирования по неделе. В свернутом виде доступны счётчик и клавиатурный expand action. Цвет дополняется текстовой/иконной семантикой.
- **Tasks:** вертикальный список по умолчанию с быстрым переключением task list, фильтрами Today / Upcoming / Overdue / Without due и поиском. Upcoming означает только сроки строго после сегодняшней локальной даты; задачи без срока не включаются в Upcoming. Колонки — отдельный явный режим; на узкой рабочей области он переключается на один вертикальный поток без потери списка/фильтра и действий.
- **Поиск:** доступен из toolbar, фильтрует содержимое текущего раздела; очистка запроса и пустой результат очевидны. Фильтры задач доступны в рабочей области и сохраняются при скрытом sidebar; дубликата группы фильтров в sidebar нет.

## Визуальные tokens

Использовать Material-inspired semantic/dynamic roles, адаптирующиеся к Light, Dark и System appearance. Primary accent — синий; значения ниже фиксируют утверждённое направление; парные значения задаёт AppTheme. Проверить на реальных экранах и состояниях контраста.

| Роль | Light | Dark | Применение |
|---|---|---|---|
| `canvas` | `#F7F9FC` | `#111318` | фон рабочей области |
| `surface` | `#FFFFFF` | `#1B1D23` | sidebar, панели, меню |
| `surface-raised` | `#FFFFFF` | `#242730` | карточка/выбранная поверхность, без тяжёлой тени |
| `text-primary` | `#202124` | `#F1F0F7` | основной текст |
| `text-secondary` | `#505866` | `#C2C5CE` | подписи, вторичная информация |
| `outline` | `#747989` | `#9297A3` | границы и неактивные контуры |
| `accent` | `#0B57D0` | `#90CAF9` | фокус, выбранное состояние, primary action |
| `event` | `#0B57D0` | `#90CAF9` | события; тональный фон плюс читаемый текст |
| `task` | `#0F6E58` | `#72D5B5` | маркер задач; не использовать цвет как единственный сигнал |
| `overdue` | `#B21C19` | `#FFB4AB` | просрочка и ошибки, всегда вместе с текстом/иконой |

- Основа — системный SF font; использовать Dynamic Type и семантические стили, не фиксировать текст в пикселях. Иерархия: заголовок периода 22–26 pt, заголовки секций 16–18 pt, основной текст 13–15 pt, метаданные не мельче 12 pt. System appearance остаётся исходным выбором.
- Компактность достигать плотной компоновкой и короткими метками, а не уменьшением кликабельной области: строки задач не ниже 44 pt, sidebar rows не ниже 36 pt с активной полной строкой; маленькие самостоятельные controls должны иметь доступный фокус и явное назначение. Сохранять контраст текста не ниже WCAG AA (4.5:1 для обычного текста; 3:1 для крупного текста и значимых графических границ).
- Радиусы умеренные и последовательные (8–12 pt для поверхностей/элементов); тонкие разделители, минимальная глубина. Избегать тяжёлых теней, декоративных градиентов и постоянно видимых карточных рамок.

## Компоненты и поведение

- Применять нативные `Toolbar`, `NavigationSplitView`, `List`, `Menu`, `Picker`, `Toggle`, `Searchable`, `DatePicker`, `Button` и контекстные меню там, где они соответствуют задаче. Не имитировать нативные меню собственными веб-подобными контролами.
- Событие показывает время, название и календарь; задача — состояние выполнения, название, срок как дату без времени, due status и task list; при наличии — локальные favorite/reminder метки. Текст и иконка дополняют цвет. Просроченные элементы заметны, но не вытесняют всё остальное визуально.
- Чётко маркировать **read-only** календарь в селекторе и в контексте события. Для него отключать создание/редактирование/удаление и показывать спокойную подсказку «Только просмотр»; не предлагать действие, которое заведомо нельзя выполнить.
- Создание/редактирование завершается явными «Сохранить» и «Отмена»; до сохранения правки остаются черновиком. Подтверждение запрашивать для разрушительных действий (удаление, массовое снятие/изменение), но не для обычного перехода или завершения задачи. Не показывать локальное действие как подтверждённую Google-синхронизацию.
- Напоминания помечать **«Локальное напоминание на этом Mac»** рядом с настройкой и в соответствующем контексте: оно не является Google Calendar notification и не меняет Google `event.reminders`. Задачи хранят локальное время; для одного timed non-recurring event пользователь выбирает точное локальное время. All-day/recurring event reminder controls показывают доступное объяснение, а не выбирают время/series scope молча. Запрашивать системное разрешение только после явного действия пользователя и объяснять результат отказа.

## Адаптация и доступность

- При широком окне сохранять sidebar и недельную сетку с читаемой минимальной шириной дня; sidebar сворачивается нативным control; узкая неделя сохраняет Week и минимальную ширину дней с горизонтальной прокруткой. Группы header переносятся целиком. Не обрезать имена и основные действия без альтернативы. Для узкой рабочей области списка задач использовать одну колонку; дополнительные колонки доступны только когда для них достаточно места.
- Клавиатура: `⌘F` — поиск, `⌘T` — Today, стрелки — переход/навигация по дням и элементам, `Space` — переключение выполнения выбранной задачи, `Return` — открыть/редактировать выбранный элемент, `⌘N` — создание в текущем контексте. Уважать системные shortcuts и показывать доступные команды в меню. В списке задач Tab или клик по свободной области переводит фокус в список; Up/Down выбирают видимые строки, Return открывает выбранную задачу, Space меняет выполнение. Свёрнутые группы и скрытые фильтром строки не участвуют. Удержание Return/Space не повторяет запись; поиск, поля форм и меню сохраняют нативное управление. Фокус видим, логичен и не сбрасывается неожиданно; все действия доступны без мыши и озвучиваются VoiceOver с названием, типом, сроком и статусом.
- Поддерживать системный Light / Dark / System, увеличение текста и Reduce Motion. Не полагаться только на цвет, hover или анимацию для объяснения состояния.

## Состояния

- **Загрузка:** сохранять заголовок и навигацию, показывать ненавязчивый progress/skeleton в рабочей области; избегать фиктивных событий/задач.
- **Пусто:** отдельные понятные состояния для пустой недели, пустого task list и отсутствия совпадений поиска. Предлагать допустимое следующее действие; для read-only календаря не предлагать создание.
- **Offline:** заметный, но ненавязчивый статус отсутствия сети; если доступен cache — показать сохранённые данные с временем последнего успешного обновления. Не показывать «изменения ожидают синхронизации» и не сохранять локальные write-запросы в очередь, пока очередь офлайн-операций действительно не реализована. Ошибка сети не должна стирать cache.
- **Ошибка:** короткое объяснение, к чему относится ошибка, и повтор действия; не заменять весь интерфейс пустым экраном. Ошибки записи не теряют несохранённый черновик.
- **Синхронизация:** компактный статус «Синхронизируется…», затем «Обновлено» или конкретная ошибка; отличать локальное сохранение от подтверждённой синхронизации, не изображать вечный spinner.
