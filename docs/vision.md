# g-calendar: продукт и видение

## Одно предложение

Локальное native macOS-приложение, которое объединяет Google Calendar и Google Tasks в спокойном week-first рабочем пространстве с привычными системными контролами и честными локальными напоминаниями.

## Пользовательская задача

Быстро увидеть рабочую неделю, календарные события и задачи вместе; перейти к нужному календарю или списку; найти сегодняшнее/просроченное; внести осознанное изменение без переключения в браузер; понимать, что уже синхронизировано, что доступно только локально и что API Google не умеет.

## Продуктовые принципы

1. Нативно прежде всего: SwiftUI + AppKit там, где нужен жизненный цикл, системные меню или API, недоступный в SwiftUI. Material-inspired визуальная дисциплина — не перенос web-компонентов в macOS.
2. Приватность локально: без собственного backend, аналитики по умолчанию и копирования OAuth secrets. Используется текущая локальная авторизация пользователя через отдельный `gws` процесс.
3. Честная синхронизация: сетевой ответ, кэш, локальное расширение и неподдерживаемое Google свойство визуально различаются.
4. Безопасные действия: реальные Google writes происходят только после явного действия в интерфейсе; удаления требуют подтверждения; read-only календарь не предлагает mutation.
5. Проверяемость: API/CLI ошибки, pagination, timezone, all-day, кеш и уведомления покрыты тестовыми fixtures; real smoke — read-only.
6. Доступность и спокойная плотность: keyboard-first для основных переходов, VoiceOver, Dynamic Type, Light/Dark/System, семантические цвета и ясные пустые/offline/error состояния.

## Область MVP

- Native `.app` для macOS, календарный вид недели и дня, переключатели календарей и task lists, список/колонки задач, Today/Overdue/search.
- Чтение реальных Calendar events и Tasks через уже настроенный `gws`; кэш последнего успешного чтения и статус синхронизации.
- Изменения событий и задач доступны только через явные UI-действия; CRUD сценарии проходят локальные fixture tests. Отдельное узкое разрешение владельца позволяет один synthetic live acceptance run через настоящий app workflow с GET/read-back; личные/production объекты и test-object deletion остаются запрещены без отдельного approval. Удаление требует подтверждения в UI.
- Локальное точное время reminder для Google Task — отдельное расширение g-calendar, маркированное local-only. Google `due` остаётся date-only.
- Системные UserNotifications через обычный macOS permission UX. Закрытие окна не равно Quit.

Подробный контракт: `docs/requirements.md` и `docs/ACCEPTANCE_CONTRACT.md`. Техническая feasibility и источники: `docs/research.md`. Визуальное направление: `docs/ui.md`.

## Вне MVP / явно не обещаем

- Полную feature parity с Google Calendar/Tasks, отдельный backend, приложение для других платформ или новый OAuth flow.
- Синхронизацию существующего Google Tasks due-time: официальный Tasks API передаёт только дату.
- Google push notifications: для них необходим внешний HTTPS callback; MVP использует пользовательский refresh/sync, не платный backend.
- Невидимую offline write queue, гарантированную доставку уведомлений во время сна Mac, автоматический запуск при логине.
- Изменение участников/отправку приглашений, одиночное изменение recurring event до реализации и тестирования точного scope.
- Публичную подпись/notarization/release без Apple Developer credentials и отдельного разрешения.

## Долгосрочный успех

Пользователь может открыть `.app`, сразу видеть актуальное содержимое Google без повторного OAuth setup; безопасно выполнить повседневные week/task workflows; отличать синхронизацию от локальных reminders; а повторяемая команда из репозитория создаёт тот же bundle без обязательного backend.
