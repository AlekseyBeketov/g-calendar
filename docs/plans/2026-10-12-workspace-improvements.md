## Surprises & Discoveries


Google Tasks API не позволяет читать или записывать время выполнения: поле `due` сохраняет только дату. Время, видимое в Google Calendar Web, нельзя надёжно получить через этот API. Исходник `Sources/GCalendar/Models.swift`, `GoogleTask.decode`, уже намеренно отбрасывает время.

Уточнение исследования: в Google UI время означает scheduled start/end работы над задачей, а deadline — отдельную дату завершения. Публичный Task.due относится к scheduled day, документация явно отличает его от deadline. Проверен живой Tasks Discovery revision20261011: 17 полей, scheduled time/end/duration/deadline отсутствуют. CalDAV не поддерживает VTODO, Apps Script повторяет public Tasks schema. Частный TasksApiService/Sync найден только как историческое наблюдение веб-запроса; собственные read/write и пригодная авторизация ещё не доказаны.

Calendar API предоставляет точное время событий через start.dateTime и настройки напоминаний: CalendarList.defaultReminders для текущего пользователя, Event.reminders.useDefault и overrides для конкретного события. При useDefault=true берутся настройки календаря, при false — только overrides; пустой набор означает отсутствие напоминаний. Для popup с minutes=N момент уведомления равен start минус N минут. Email-настройки не преобразовываются в macOS banner. Изменение reminders не изменяет event.updated, поэтому сравнение только updated пропускает важные изменения расписания. Текущие CalendarInfo и CalendarEvent не сохраняют reminders, хотя list/get запрашивают полные ресурсы; это пробел модели приложения, а не ограничение REST.

`tasks.clear` помечает выполненные задачи скрытыми, а не удаляет. Приложение запрашивает `showHidden: true` в `Sources/GCalendar/GWSClient.swift`, поэтому простое подключение clear не решает запрос пользователя.

В eco-web индексы вынесены в `/Users/alexbeketov/ecology/eco-web-caches/eco-web-fdd623cf79/`. Manifest содержит repository path, commit, dirty state, версии и время. Для g-calendar пользователь явно требует индексы внутри корня: это исключение из общего навыка `code-indexing`.

Установлены `graphify`, `tgrep` и `openspec`. Структурный поиск и индексация остаются отдельными операциями. Граф локализует кандидатов, исходники подтверждают поведение.

Календарная сетка использует три синхронизированных NSScrollView; задачи — SwiftUI ScrollView. Плавность нельзя обеспечивать длинной анимацией всех изменений SwiftUI: она ухудшит отклик и синхронизацию.

При добавлении UI-состояния дважды воспроизведён missing SwiftUIMacros.StateMacro в CLT SDK, включая явное initial value. Выполнены TinyFish поиск и Context7 StateObject docs. Рассмотрены полный Xcode, согласованный compiler/SDK, загрузка официального macro plugin и существующий StateObject/ObservableObject подход. Выбран StateObject: подтверждён документацией Apple и используется текущим кодом, не требует системных изменений. Первичный API-источник: https://developer.apple.com/documentation/swiftui/stateobject. Новый TaskWorkspaceInteraction хранит drag и подтверждённый набор удаления.

## Context and Orientation


Рабочий каталог — `/Users/alexbeketov/g-calendar`. Это macOS приложение на SwiftUI/AppKit с двумя транспортами Google: запуск `gws` и прямой REST/OAuth. `Sources/GCalendar/AppMain.swift` содержит `WorkspaceViewModel`, состояние, синхронизацию, применение подтверждённых mutations и lifecycle. `Models.swift` содержит GoogleTask и CalendarEvent. `CalendarLayout.swift` содержит чистые функции фильтров, групп и размеров досок.

`TaskWorkspaceView.swift` отображает список и колонки, управляет редакторами и клавиатурной навигацией. `TaskKeyboardNavigation.swift` определяет составную идентичность задачи: доска плюс task ID. `SettingsAndForms.swift` содержит настройки, редакторы задач/событий и ручные напоминания. `AppViews.swift` содержит RootView и SidebarView. `CalendarScrollOffsetObserver.swift` содержит `CalendarScrollRegionsView` с синхронизированными шкалой, заголовком и сеткой.

`Reminders.swift` содержит scheduler UserNotifications, foreground delegate, ReminderCoordinator и EventReminderCoordinator. `Cache.swift` хранит локальные metadata. `RuntimeModes.swift` разделяет normal, demo и тестовые режимы, включая контексты транспортов. `RefreshCoordinator.swift`, `CalendarRangeCache.swift` и `WorkspaceSnapshotReducer.swift` обеспечивают частичные чтения и защиту от устаревших результатов. Частичная загрузка — чтение части календарей или дат; отсутствие события в ней не доказывает удаление.

`GWSClient.swift` формирует разрешённые вызовы, `GoogleRESTTransport.swift` преобразует их в HTTP, `MutationService.swift` проверяет результат чтением Google, `MutationRecovery.swift` хранит незавершённые проверки. Read-back означает повторное чтение результата записи; при неопределённости нельзя автоматически повторять запись.

Спецификации находятся в `openspec/changes/g-calendar-mvp/`. Активный change — `g-calendar-mvp`, схема spec-driven. Старые завершённые задачи не переоткрывать; добавить новый раздел с восемью фичами. `Tests/InvariantTests.swift` и `Tests/GoogleRESTTests.swift` запускаются через `scripts/test.sh`; UI fixture проверка — `scripts/test-native-ui.sh`, только если нужна для изменяемых нативных компонентов. Работа через браузер и synthetic Google mutations требуют запрошенного явного разрешения согласно правилам проекта.

Создать `Sources/GCalendar/AutomaticNotifications.swift` с чистым планировщиком: он получает подтверждённые события/задачи, локальное время, текущий момент, часовой пояс и настройки, возвращает будущие запросы. Задачи без точного локального времени и события на весь день исключаются. В CalendarInfo сохранить defaultReminders, в CalendarEvent — reminders.useDefault и overrides, с совместимостью старого кэша: неизвестные настройки не считать отключёнными и не выдумывать fallback. Источник расписания событий — актуальные настройки Google для текущего пользователя. Для каждого применимого popup reminder вычислить start минус minutes; email не порождает локальный banner. При useDefault=false пустые overrides отменяют напоминания, даже если defaultReminders календаря непустой. Уведомления имеют устойчивый ID из контекста аккаунта, типа ресурса, доски/календаря, task/event occurrence ID и reminder offset; одинаковые popup offsets дедуплицируются. Повторяющиеся события представлены отдельными экземплярами Google, с исключениями и переносами; не использовать повторяющийся OS trigger для всей серии.

Добавить сериализованный coordinator, сравнивающий желаемые запросы с pending запросами OS: добавлять новые, заменять изменённые, отменять доказанно неактуальные, оставлять неизменённые. Сериализация означает, что одновременно только один пересчёт пишет расписание; новую ревизию данных проверять после await. Сохранять состояние применённой ревизии и безопасную диагностику без названий/ID в логах. Ошибка scheduler сохраняет возможность повторной сверки и показывается в настройках; нельзя подавлять все ошибки через try?.

Подключить независимое от открытой недели чтение календарей, events и полного текущего набора задач. Планировать notification triggers ближайших 30 дней; читать события с запасом вперёд до максимального документированного offset (40320 минут), иначе раннее напоминание о более далёком событии потеряется. Проверить актуальный допустимый предел при реализации. Повторять сверку после успешной синхронизации, подтверждённой mutation, запуска, activation, wake и смены timezone/дня. Изменения calendar defaults пересчитывают все наследующие события; изменения event reminders учитываются независимо от event.updated. Фоновый refresh при работающем приложении ограничить интервалом, coalescing существующего refresh coordinator и лимитом параллельных чтений; не создавать таймер на каждую задачу. Запланированные запросы передаются macOS заранее. Не обещать обнаружение удалённых изменений, когда приложение завершено, или уведомление спящего устройства.

Удаление pending допускается только при подтверждённом удалении, завершении, полном чтении соответствующей доски либо полном покрытии нужного календарного интервала. Кэш и частичная/ошибочная загрузка не отменяют отсутствующие в ней ресурсы. Переименование/перенос времени заменяют содержимое и trigger; завершение/удаление отменяют pending, но не стирают без необходимости уже доставленную историю. ## Idempotence and Recovery


Индексы производные и пересоздаваемые; force удаляет только содержимое выбранного cache, не исходники. Manifest не объявляет полный успех при частичном сбое. Автоматические уведомления используют стабильные IDs и сериализованный diff, не дублируют запросы после рестарта. Миграция локальных данных версионирована и сохраняет архив; write failure не уничтожает исходную запись.

Google mutations выполняются только явными действиями UI. Неопределённый результат проверяется чтением через recovery; новая запись не отправляется для проверки предыдущей. Отказ сети сохраняет last-known-good snapshot и pending расписание до доказанной смены состояния. Сборочный скрипт сохраняет предыдущий bundle при неудаче. Коммиты не переписываются и не пушатся.
