# ADR-0002: Google REST с обязательным входом при первом запуске

- Статус: accepted 2026-10-15
- Контекст: после проверки первого пользовательского сценария выяснилось, что обязательная установка `gws` и ручной импорт OAuth JSON делают приложение недоступным для обычного пользователя. Владелец выбрал прямой Google OAuth/REST основным транспортом, а `gws` — дополнительным выбором в настройках. Передан публичный OAuth Client ID приложения.
- Решение: первый запуск показывает отдельный экран входа в Google и не открывает календарь до успешной авторизации. Native OAuth использует PKCE и loopback callback; refresh token хранится в macOS Keychain. Client ID включается в bundle как публичная конфигурация, секрет и токены в bundle не помещаются. `gws` не устанавливается автоматически и доступен только как opt-in транспорт в настройках. После успешного входа запускается чтение календарей и задач; записи остаются явными действиями пользователя.
- Последствия: вход зависит от корректного Desktop OAuth client, включённых Calendar/Tasks APIs, consent screen и его аудитории. Владельцу нужно проверить живой вход и доступы Google Cloud; локальная сборка не доказывает состояние OAuth-проекта. Существующие токены не мигрируются и остаются в Keychain. Незавершённый журнал записи продолжает запрещать небезопасное переключение транспорта.
- Распространение: Apple Developer Program не используется. Локальные ad-hoc сборки и DMG не обещают обычный Gatekeeper запуск; обновления выполняет Sparkle с EdDSA-подписью ленты и архива; private key хранится в Keychain. При текущей сборке без Library Validation Developer ID для этого механизма не требуется.
